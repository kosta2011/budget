TASK-12 — Централизованное логирование (ELK)
Цель: Организовать сбор, хранение и визуализацию логов монолита, API Gateway и (опционально) других сервисов с помощью стека ELK (Elasticsearch, Logstash, Kibana), поднимаемого в Docker Compose.
Что сделано
1.	Добавлена зависимость в pom.xml монолита и Gateway
net.logstash.logback:logstash-logback-encoder (версия 7.4) – для отправки логов в формате JSON в Logstash.
2.	Создан файл logback-spring.xml в src/main/resources каждого приложения
o	Логи дублируются в консоль (как обычно) и отправляются по TCP на порт 5044 в Logstash.
o	Добавлено пользовательское поле app_name, которое подставляется из spring.application.name, чтобы различать логи монолита и Gateway.
o	Используется стандартный Logstash-аппендер.
3.	Создана конфигурация Logstash
o	В корневой папке проекта (рядом с docker-compose.yml) создана папка logstash.
o	Внутри создан файл logstash.conf с простой логикой: слушать TCP-порт 5044, принимать JSON-логи, отправлять их в Elasticsearch (индекс apps-logs-YYYY.MM.dd), а также выводить в stdout контейнера для отладки.
4.	Добавлены сервисы ELK в docker-compose.yml
o	Elasticsearch – хранилище логов, ограничена память (2 ГБ), отключена проверка подлинности для локальной разработки.
o	Logstash – приёмник логов, монтируется конфигурационный файл.
o	Kibana – веб-интерфейс для просмотра и анализа логов.
o	Создано именованное хранилище es_data для сохранения данных Elasticsearch между перезапусками.
o	Все три сервиса подключены к общей сети budget-net.
5.	Настройка Kibana
o	После запуска создан Index Pattern apps-logs-* с полем времени @timestamp.
o	В разделе Discover доступен поиск и фильтрация логов, в том числе по полю app_name (можно смотреть логи только монолита или только Gateway).
6.	Учёт ресурсов
o	Elasticsearch ограничен по памяти (ES_JAVA_OPTS), что предотвращает чрезмерное потребление ОЗУ.
o	При наличии 64 ГБ ОЗУ лимиты можно увеличить до 4 ГБ без ущерба.
Проверка
•	Запуск Docker Compose: docker-compose up -d --build.
•	Логи приложения начинают поступать в Elasticsearch.
•	Открытие Kibana по адресу http://localhost:5601, создание Index Pattern, просмотр логов в Discover.
•	Фильтрация по app_name (например, monolith или gateway) для раздельного анализа.
Результат
Централизованное логирование избавляет от необходимости выполнять docker-compose logs для каждого сервиса. Все логи доступны в едином интерфейсе с возможностью поиска, фильтрации и визуализации. Это облегчает отладку и мониторинг приложения.
